Stack: 
	It is an Abstract, Linear data structure with a pre-defined capacity.
	Its a linear collection of items where items are inserted or removed based on a particular order.
	It specifies the operation and behaviour without specifying how the data is stored or implemented.

	Stacks are great for processing nested structures, and are important for understanding Recursion.
	Important: Insertion and Deletion happens at the same end in a Stack (top end)

	Real-life uses: 
	- Undo, Redo function in any text editor.
	- Memory management
	- backtracking algorithms

	Methods: 
	pop(): removes element from the Stack and return it.
	push(element): adds element to the Stack
	isEmpty(): Returns true when a Stack is empty
	peek(): Returns value of the top element 
	search(Object obj): Checks whether the given obj is present in Stack and if yes, returns its position from the top of the Stack. Otherwise, it returns "-1"
	size(): returns current size of the Stack.

	Ask this question - "Does this problem involve undo, backtracking, matching, or previous elements?". If the answer is yes, then use Stacks.
		- undo/backspace
		- matching pairs (), {}, []
		- previous greater/smaller
		- expression evaluation
		- Reversals

	Stack implementation: 
	- Stack: Usually not recommended, as it extends Vector interface an Vector is synchronized. And synchronization in unnecessary overhead here.
	- ArrayDeque: Preferred for Stack implementation in Java.
	- LinkedList: Not preferred as it has memory overhead because of nodes.

	Deque<Character> stack = new ArrayDeque<>();
	Here, Deque is the Interface and ArrayDeque is the implementation.

Difference between distributed services and cloud native services.
	Definitions: 
		Distributed systems describe how the system in split into multiple components that communicate over the network.
		Cloud-native describes how a system is designed, developed, and operated to run effectively in the cloud environments, emphasizing
	scalability, resilience and automation

Differences beween Distributed systems and Microservices: 
	Definitions: 
		Distributed systems describe how the system in split into multiple components that communicate over the network.
		Microservices: Its an architectural style where a system is built as a collection of small, independently deployable services, 
each having its own business capability and communicating via APIs or events.

	Differences: 
	- Service Autonomy: 
		Distributed services are often deployed together, failed together. Whereas, 
		Microservices are independently deployable, scalable and fail in isolation.
	- Business capability.
	- Data ownership
		Distributed services share databases, tight coupling via data
		Microservices have each of their own database (ideally), integration via APIs, events.
	- Failure model
		Distributed services: cascading failures are normal
		Microservices: failures are isolated to independent Microservices.

	We can have: 
	- distributed systems that are not cloud-native
	- distributed systems that consist of Microservices
	- Microservices that are not cloud-native
	- Cloud native systems that use Microservices.
	All Microservices are distributed systems, but not all distributed systems are Microservices.


Cloud native application design: 
	Cloud-native describes how a system is designed, developed, and operated to run effectively in the cloud

	From a design perspective, cloud-native systems (SHLFE)
	- stateless (	- They assume that instances can be restarted at any time, so state is externalized to managed stores.)
	- horizontally scalable
	- loosely coupled (communicate through APIs or events)
	- failure-tolerant
	- emphasize automation (IaaC, CI/CD, observability)

	It's not about "running an app on AWS".
	It's about how the app is designed, not just where it runs.

Linked Lists: 
	It is a DS where each element is stored independently in memory - and each node has 2 things: value and reference (or called as pointer) to next node.
	The last node points to null, which signals the end of linked list.
	The only entry point you have is the head - the first node.
	So, no index. No random access.
	To reach the 4th element, you must walk through the head. It takes O(n) TC.


	class ListNode {
		int val;
		ListNode next;

		ListNode (int val) {
			this.val = val;
			this.next = null;
		}
	}

	// assume you have head pointing to first node.
	// Now, create a new variable for iterating through the linked list. Name it current for making it easy to understand.

	ListNode current = head; // as we will be starting from head.

	while (current != null) { // iterate until the last node. As last node will have its pointer as null, we use 'current != null'
		System.out.println(current.val);
		current = current.next; // next is the variable in each node like val. But next contains the reference to another node. 'current.next' gives that reference of the actual node.
	}

	When we write current.next, we are just establishing the link.
	
	In a Single Linked list, you cannot go back. 
	So in the problem of Reverse linked list, you thought of a solution to find the end and traverse backwards. But single linked list just has "next" but not "prev" reference.
