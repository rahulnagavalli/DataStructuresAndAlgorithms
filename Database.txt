Distributed Atomicity:
  Why Atomicity is hard in distributed systems (due to partial failures).
  It can be achieved using: 
  Two phase commit 
  Three phase commit 
  Saga pattern
  Outbox pattern
Tradeoffs between Atomicity and Availability.



Idempotency and Compensation; 
  When strict Atomicity is not possible (Eg: In Microservices), system rely on
  1. Idempotent operations (retries don't change outcome)
  2. Compensating transactions (reverse a failed step)
  3. Event-driven design (using queues to ensure eventual consistency)

Eg: In Microservices, 
Step 1: Deduct Payment
Step 2: Reserve Inventory
Step 3: Create Order.
If Step 3 fails, trigger compensation = refund payment + release inventory.

Database Normalization: 
  It is used in Relational Database systems to organize tables to reduce Data Redundancy and improve Data Integrity.
  It involes applying a set of rules known as Normal Forms. 
  Primary goals of Database Normalization are: 
  1. Eliminate Redundancy: Storing same piece of data multiple times can waste storage and cause storage inconsistencies.
  2. Improve query performance.
