API Design:

Application Program Interface.
API's enable 2 software components to communicate with each other using a set of definitions and protocols.

Two main protocols:
- REST: Has Http Methods and Resources represented as URL's 
  - Resource: They represent the data that is being acted upon.
  - REST endpoint describe Resources and not Verbs.
  - For naming, use plural Nouns.
  - Here, Resources map directly to core entities;
  - Eg: GET /events
        GET /events/{id} -> Here, we use Path parameters if we want to specify the resource that we want to work with. or identify a resource.
        GET /events/{id}/tickets
        GET /events?city=LA&date=2025-01-01 -> Here we use Query parameters if we want to specify optional filters.
  - Dont use verb in the API endpoint. Verb is always the HTTP method.
    Eg: POST /events/create -> This is wrong.
        POST /events -> This is correct.
- GraphQL: It lets the clients request exactly the data that they need using queries. Reduces over-fetching and under-fetching.
