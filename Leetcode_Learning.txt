Bucket Sort:

- As we get time as O(nlogn) using normal sorting, we can use bucket sorting instead.
- Bucket sorting allows us to group elements by frequency and directly access high frequency groups.
- Since the maximum frequency of any number can't be more than n (length of the array), we can use an array of size n+1
  where index=frequency.

- This problem can be done using - Array of lists OR List of lists. 

List<Integer>[] bucket = new List[nums.length + 1]
vs
List<List<Integer>> bucket = new ArrayList<>();

Array of Lists:
Use when you care about speed and memory and know about size in advance.
Pros:
- Faster index access - a[i] compared to a.get(i)
- Less memory overhead when compared to resizing ArrayList.

Cons:
- If we use this, there will be compiler warning saying raw array is used.
- Java doesn't allow creation of generic arrays, so it is technically unsafe.

List of lists:
Use when you need flexibility, dynamic resizing and cleaner code.
Pros:
- Avoids Java's type safety issues.
Cons:
- takes more memory - as ArrayList stores references and has dynamic resizing.

When Should Bucket Sort Come to Mind?
  Whenever the problem mentions:
  
  ✅ Frequencies (e.g. "most frequent", "least frequent")
  ✅ Fixed or bounded value ranges
  ✅ Top-K or group-by-frequency problems
  ✅ Avoiding O(n log n) sorting when better is possible

Longeset SubString Without Repeating Characters:

Brute force approach:
- need 2 for loops, where first loop is for starting index and second loop is for moving the pointer forward. (i for start of a new window and j for expanding the new window)
- create the Set inside outer for loop, as each outer loop represents start of a new window, so the set must be re-initialized for that start.

set.contains() -> referred as lookup.
set.add() -> referred as insertion.

In case of Brute force approach, 
- we are checking too much - checking the substrings that are overlapping.
- there has to be a way to avoid duplication.
- this is where sliding window helps.

Sliding window:
- As we are moving j to expand the window, if we find a duplicate character, moving i forward until the window becomes valid again.

This can be achieved using HashSet and HashMap.

Exmple: abcabcbb

i    j    set
0    0    a
0    1    ab
0    2    abc
0    3    Here, a is duplicate. So, start by removing from left end. Then, set becomes bc
1    3    bc doesn't contain a, so goes to next step and adds "a" to "bc", making it "bca"
1    4    Here, existing set is "bca" and new character is "b", so it is duplicate. Start by removing left most character using "i". Then set becomes "ca"
2    4    "ca" doesn't contain "b", so add it. Now set becomes "cab"
2    5    Here, existing set is "cab" and new character is "c", so it is duplicate. Start by removing left most character using "i". Then set becomes "ab"
3    5    "ab" doesn't contain "c", so add it. Now set becomes "abc"
3    6    Here, existing set is "abc" and new character is "b", so it is duplicate. That means, duplicate could be present anywhere between i and j-1. Start by removing left most character using "i". Then set becomes "bc"
4    6    

HashSet - 
int i, maxLen = 0;
Set<Character> set = new HashSet<>();
for (int j = 0; j< s.length(); j++) {
  while (set.contains(s.charAt(j)) {
    set.remove(s.charAt(i));
    i++;
  }
  set.add(s.charAt(j));
  maxLen = Math.max(maxLen, j-i+1);
}

** We have to remove characters from the left until the first occurrence of duplicate character is kicked out. (That's why, we have i++ in the while loop)
** We shrink the window from the left until the duplicate character is removed.

Two Sum:

Patterns:
  - basic left-right pointer logic: (converging pointers: l++, r--)
    - Use when you want to get pairs (like in 2 sum when array is sorted, valid palindrome, container with most water etc. )
    - Use 2 pointers - each start from the end of the given array: then if sum is equal, then return the answer. If sum is less than target, increment left pointer and if sum is greater than target, decrement right pointer.
    - for "while" loop condition, make sure if you want to repeat the indices or not. while (l <= r) suggests that you want to do the operation on element present at single index (Eg: nums[1] + nums[1]). If not, use 
while (l < r)

  - Fast and Slow pointers (one pointer will go fast and other pointer will go slow based on some condition)
    - Use when you are building/modifying the Array in-place. (like in, Remove duplicates from sorted Array, Move Zeroes, Remove Element etc. )
    - Here, there's no strict rule that both pointers start at 0 and 1 index respectively. It depends on the approach. But one of the pointer moves fast and other moves slow - that is the rule.
